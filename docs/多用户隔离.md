# 多用户隔离

本文档记录 Novare 平台多用户隔离安全修复的完整内容，涵盖 5 个安全问题及其修复方案。

---

## 1. Web 模式内置文件工具使用全局 workspace

### 问题

`web/backend/agent_service.py` 初始化时创建了全局 `ToolRegistry(workspace=self.config.workspace)`。当 Web 多用户模式下不同用户调用 `read_file`、`write_file`、`edit_file`、`glob_search`、`grep_search` 这些内置文件工具时，所有用户的文件操作都指向同一个全局 workspace，而不是各自隔离的 `get_user_workspace(user_id)`。

这意味着用户 A 的 agent 可以读写用户 B 的文件。

### 修复

**`novare/tools/registry.py`**

- 新增 `_FILE_TOOLS` 集合，列出需要 workspace 隔离的 5 个文件类工具。
- 在 `ToolRegistry.execute()` 中，对文件类工具检查 `tool_context` 是否包含 `workspace` 键：如果有，用 `tool_context["workspace"]` 覆盖默认的 `self.workspace`；否则保持原有行为。

```python
_FILE_TOOLS = {"read_file", "write_file", "edit_file", "glob_search", "grep_search"}

# execute() 中：
if name in _FILE_TOOLS and tool_context and "workspace" in tool_context:
    kwargs["workspace"] = Path(tool_context["workspace"])
```

**`web/backend/agent_service.py`**

- 将 `tool_context` 从 `{"user_id": user_id}` 扩展为 `{"user_id": user_id, "workspace": str(self._workspace_for(user_id))}`。
- CLI 模式（`user_id=None`）时 `tool_context` 仍为 `None`，文件工具使用全局 workspace，行为不变。

### 影响范围

- Web 用户的文件工具操作限定在自己的 workspace 内。
- CLI 模式行为不变。
- MCP 工具和 `reviewer_evaluate` 不受影响。

## 2. RAG brute-force fallback 读取全量 embeddings

### 问题

`mcp-server/tools/rag_query.py` 中的 `_brute_force_search()` 存在两个严重的多用户隔离漏洞：

1. **先读后过滤**：调用 `get_all_embeddings(conn)` 读取所有用户、所有论文的全部 embeddings，然后才在内存中根据 `allowed_paper_ids` 过滤。当数据量大时不仅性能差，更在逻辑上暴露了全库数据。
2. **静默降级**：`_get_user_paper_ids(user_id)` 查询失败时返回 `None`，导致 `_brute_force_search()` 不做任何过滤，直接搜索全库。
3. **无 user_id 时默认全库检索**：`handle_rag_query` 在没有 `user_id` 的情况下仍然允许全库 RAG 检索。

### 修复

**`mcp-server/core/database.py`**

- 新增 `get_embeddings_by_paper_ids(conn, paper_ids)` 函数，在 SQL 查询层通过 `Chunk.paper_id.in_(paper_ids)` 过滤，只返回指定论文的 embeddings，避免读取全量数据。

**`mcp-server/tools/rag_query.py`** — 全面 fail-closed 重写

| 组件 | 旧行为 | 新行为 |
|---|---|---|
| `_get_user_paper_ids` | 查询失败返回 `None` | 抛出异常（fail-closed） |
| `_brute_force_search` | 调用 `get_all_embeddings()` 后内存过滤 | 调用 `get_embeddings_by_paper_ids()`，SQL 层 scoped |
| `handle_rag_query` 入口 | 无 `user_id` 时默认全库检索 | 无 `user_id` 拒绝（除非 `RAG_ALLOW_UNSCOPED=true`） |
| `total_chunks` 统计 | 再次调用 `get_all_embeddings()` | 使用 scoped 查询结果的长度 |
| `get_all_embeddings` 导入 | 模块顶层 import | 仅在 `ALLOW_UNSCOPED` 路径中延迟导入 |

安全策略：
- **默认 fail-closed**：无 `user_id` → 拒绝；权限查询失败 → 拒绝；用户无论文 → 空结果。
- **CLI 兼容**：设置 `RAG_ALLOW_UNSCOPED=true` 环境变量才允许无 `user_id` 全库检索。
- **Milvus 不受影响**：仍按 `user_id` partition 查询。

## 3. paper_parse 本地文件路径越权

### 问题

`mcp-server/tools/paper_parse.py` 的 `handle_paper_parse(args, user_id)` 支持 `file_path` 参数解析本地 PDF 文件，但存在两个漏洞：

1. **路径未校验**：只做 `os.path.exists(file_path)`，没有校验文件是否属于当前用户的 workspace。用户/agent 如果知道其他用户上传文件的路径，可以通过 `paper_parse(file_path=...)` 解析别人的文件。
2. **pdf_path 复用无权限检查**：当传入 `paper_id` 且数据库里已有 `paper.pdf_path` 时，代码直接复用该路径。私有论文的权限检查只在 `existing_chunks` 分支里做，如果私有论文有 `pdf_path` 但还没有 chunks，权限边界不够硬。

### 修复

**新增 5 个 helper 函数：**

| 函数 | 作用 |
|---|---|
| `_resolve_user_workspace(user_id)` | 返回用户 workspace 的 resolved `Path` |
| `_is_relative_to(path, root)` | 判断路径是否在 root 之下（兼容 Python <3.9） |
| `_validate_user_local_file(file_path, user_id)` | 校验文件路径在用户 `uploads/` 或 `papers/` 下；拒绝 `../` 和 symlink 逃逸；无 `user_id` 默认拒绝 |
| `_user_has_fulltext_access(user_id, paper_id)` | 查 UserPaper 表是否有 `has_fulltext_access=True` |
| `_can_reuse_paper_pdf(paper, user_id)` | 判断用户是否可复用已有 pdf_path |

**`_validate_user_local_file` 逻辑：**

```
无 user_id → 拒绝（ALLOW_UNSCOPED_LOCAL_FILE_PARSE=true 时放行）
有 user_id → resolved = Path(file_path).resolve()
allowed_roots = [user_workspace/uploads, user_workspace/papers]
resolved 必须在 allowed_roots 之一下面（防止 ../ 和 symlink 逃逸）
resolved 必须存在且是文件
```

**`_can_reuse_paper_pdf` 逻辑：**

```
public paper + pdf_path 在 public_papers 公共缓存目录 → 允许
public paper + pdf_path 在某个用户目录 → 需要 owner 或 has_fulltext_access
private paper → 仅 owner 或 has_fulltext_access
无 pdf_path → False
```

**`handle_paper_parse` 修改点：**

1. **file_path 分支**：从简单的 `os.path.exists` 改为调用 `_validate_user_local_file`。
2. **pdf_path 复用分支**：新增 `_can_reuse_paper_pdf` 权限检查。
3. **existing_chunks 分支**：private 论文检查增加 `_user_has_fulltext_access` 支持。
4. **existing_row.pdf_path 更新**：新增 private 论文的 owner/access 权限检查。

## 4. /api/papers/pdf/view 本地 PDF 访问过宽

### 问题

`web/backend/routes/papers.py` 的 `get_paper_pdf()` 端点中，本地 PDF 文件的访问权限判断为：

```python
is_owner = (
    paper.visibility == "public"
    or paper.created_by_user_id == user.id
    or user_paper_repo.has_fulltext_access(paper_id)
)
```

`paper.visibility == "public"` 只表示论文元数据公开（如 arxiv 论文的标题、摘要），但当前代码将其等同于"本地 PDF 文件公开"。如果一篇 public 论文的 `pdf_path` 指向某个用户上传/解析的本地私有文件，任意已登录用户都能读取该文件全文。

### 修复

**新增 helper 函数：**

| 函数 | 作用 |
|---|---|
| `_is_relative_to(path, root)` | 路径归属判断 |
| `_public_papers_dir()` | 公共缓存目录，与 `paper_parse.py` 保持一致 |
| `_is_public_cached_pdf(pdf_path)` | 判断 pdf_path 是否在 `public_papers/` 下 |
| `_can_view_local_pdf(paper, user, repo)` | 三条放行路径的统一判断 |

**`_can_view_local_pdf` 逻辑：**

```python
if paper.created_by_user_id == user.id:        # owner → 允许
    return True
if user_paper_repo.has_fulltext_access(paper.id):  # 有全文权限 → 允许
    return True
if paper.visibility == "public" and paper.pdf_path and _is_public_cached_pdf(paper.pdf_path):
    return True                                  # public + 公共缓存目录 → 允许
return False                                     # 其他 → 拒绝
```

**权限变更对照：**

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| `paper.visibility == "public"` 单独 | ✅ 任意用户可读 | ❌ 不再单独授权 |
| public + pdf_path 在 `public_papers/` | ✅ | ✅ 公共下载缓存，允许 |
| public + pdf_path 在用户 workspace | ✅ **泄漏** | ❌ 需 owner 或 fulltext_access |
| owner (`created_by_user_id`) | ✅ | ✅ 不变 |
| `UserPaper.has_fulltext_access` | ✅ | ✅ 不变 |
| 外部 arxiv / paper.url 重定向 | ✅ | ✅ 不受影响 |

## 5. 子智能体文件工具未继承用户 workspace

### 问题

主 agent 通过 `agent_service.py` 传入 `tool_context={"user_id": user_id, "workspace": str(workspace)}`，使文件类 builtin 工具使用用户隔离 workspace。但 `novare/subagents/tools.py` 的 `handle_spawn_subagent()` 调用 `run_subagent()` 时只传了 `tool_context={"user_id": user_id}`，**遗漏了 `workspace`**。

结果：子智能体调用 `read_file`、`write_file` 等文件工具时，由于 `tool_context` 中没有 `workspace`，registry 的 `execute()` 方法 fallback 到全局 `ToolRegistry.workspace`，存在跨用户 workspace 风险。

### 修复

**`novare/subagents/tools.py`** — 3 行改动：

```python
# 旧行为：
tool_context={"user_id": user_id} if user_id else None,

# 新行为：
child_tool_context = None
if user_id:
    child_tool_context = {"user_id": user_id}
    if workspace:
        child_tool_context["workspace"] = str(workspace)
```

从 `kwargs` 中提取 `workspace`（由 `register_subagent_tools` 注入的 default_tool_context 提供），在构建子智能体 `tool_context` 时一并传递。

### 影响范围

- 子智能体的文件工具使用与父 agent 相同的用户 workspace。
- CLI/无 user_id 模式行为不变（`tool_context` 仍为 `None`）。
- MCP 工具和 `reviewer_evaluate` 不受影响。
